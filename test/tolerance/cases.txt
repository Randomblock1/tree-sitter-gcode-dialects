# Where tolerance stops.
#
# This grammar is deliberately permissive: it accepts unknown commands, vendor
# arguments, and glued compact lines, because an editor that reports half a
# file as broken is worse than one that highlights an unfamiliar command. A
# no-ERROR corpus sweep therefore proves very little on its own — a grammar
# that accepted every byte would pass it. These cases fix the boundary from
# both sides.
#
#   reject: the parser must produce an ERROR. Only structural malformedness
#           qualifies — unbalanced delimiters, an operator with no operand, a
#           keyword whose required operand is missing.
#
#   accept: the parser must NOT produce an ERROR, and must produce the listed
#           nodes if any are named after "->". These are the forms that look
#           wrong to someone who has only read a G-code tutorial but that real
#           controls accept, plus the cases where the right tree is not the
#           obvious one. A node written "!name" must be ABSENT.
#
#   tolerate: input a real control rejects that this grammar accepts anyway.
#           Every one of these is here because one grammar serves four
#           dialects and the construct is legal, or unavoidably ambiguous, in
#           at least one of the others. Listing them keeps the leniency
#           reviewable instead of invisible; tightening one is then a
#           deliberate change to this file, not an accident.
#
# What is deliberately NOT here: anything a syntax layer cannot know. An
# "endif" with no "if", a checksum whose arithmetic is wrong, an unknown
# command, a G1 with no axis words, a duplicate axis word — all of those are
# the firmware's business, and a line-oriented grammar that guessed at them
# would be wrong on the many files that legitimately span those constructs.
#
# Two entries below pin the readings of "#[", which the lexer has to tell
# apart: LinuxCNC indirection and a commented-out Klipper section. Getting that
# wrong is invisible to an ERROR-only sweep — 942 lines of NativeCAM
# indirection once parsed as comments while the corpus still reported clean.
#
# Everything from the first "---" on is case data, so no comment lines appear
# past this point: a case body may itself start with "#".

--- reject: unterminated bracket expression
#100 = [1 + 2

--- reject: stray closing bracket
#100 = 1 + 2]

--- reject: binary operator with no right operand
